## 1. 이번 제작의 목적

사용자의 최신 요청에 따라 **레퍼런스로 보여줄 수 있는 홈페이지의 시각적 완성도**를 첫 목표로 둔다. 실제 객실 사진의 크기와 순서, 화면의 깊이, 타이포그래피, 장면 전환, 목적에 따른 객실 탐색을 먼저 구현한다. 백엔드와 키워드 확장은 후속 단계로 둔다.

현재 산출물은 아르보를 위한 반응형 1페이지 시안이다. 고객이 사진을 보고 객실을 탐색하는 핵심 행동은 이번 화면에 포함한다. 운영정보는 확인한 범위로 표현하며, 미확인 수치와 서비스를 분위기 문장으로 채우지 않는다.

## 4. 이번 화면의 흐름과 선택 이유

1. **실제 사진과 완만한 패럴랙스 히어로** — 공간을 먼저 보고 머무를 장면을 상상한다. 과한 확대나 원근 변형으로 실제 구조를 다르게 보이게 하지 않는다.
2. **문장 한 숨** — 사진 다음에 짧은 문장과 여백을 두어 탐색의 속도를 낮춘다. 설명을 읽어야 다음 화면을 이해할 수 있는 구조를 피한다.
3. **목적 선택과 큰 객실 이미지** — 방문 목적을 누르면 사진과 설명이 함께 바뀐다. 정원·재고·가격을 추정해서 추천하지 않고 확인한 객실 차이를 앞당겨 보여준다.
4. **시그니처 공간 경험** — 객실 전경과 시설의 관계가 드러나는 사진을 연결한다. 구체적인 공간이 감각적 문장의 근거가 되게 한다.
5. **갤러리** — 큰 장면에서 발견한 관심을 세부 사진으로 이어간다. 사진의 객실 연결과 의미 있는 대체 텍스트를 유지한다.
6. **도착·FAQ** — 주소와 예약 전에 확인할 질문을 정리한다. 운영 승인값이 없는 답을 임의로 만들지 않는다.
7. **OTA 링크** — NOL·여기어때에서 날짜·요금·취소·상품 조건을 확인하도록 안내한다. 외부 이동을 예약 완료로 표시하지 않는다.

UP → DOWN → UP은 ‘공간에 대한 기대 → 나에게 맞는 객실을 고르는 질문 → 선택한 공간을 더 자세히 보는 흐름’으로 해석한다. 첫 화면의 감각과 후반의 정보가 동일한 실제 공간을 설명하도록 연결한다.

## 5. 사진 사용과 실제 공간 보존

현재 확인한 원본·보정 자료를 시안에 활용한다. 사용자가 자료 활용을 요청했다는 사실과 호텔 운영자의 고객 공개 승인은 별도로 기록한다. 파일명만으로 실제 객실·촬영일·사용권·공개 승인 여부를 확정하지 않는다.

- 객실 벽 구조, 침대, 면적, 전망, 시설을 생성·확장한 이미지가 섞이지 않도록 확인한다.
- 노출·색·수평·크롭을 조정한 보정본도 원본과 현재 객실을 대표하는지 확인한다.
- `ai-review-not-upload`는 정적 에셋·공유용 결과물에서 제외한다.
- 사진에 보이는 특정 시설을 전체 객실의 공통 제공 사항으로 설명하지 않는다.
- AI 인물을 실제 고객·직원·후기 작성자로 표시하지 않는다.
- 아르보 사진과 문안은 다른 사업장의 예시 콘텐츠로 자동 재사용하지 않는다.

## 6. 아직 확정하지 않은 운영값

아래 값은 기존 자료만으로 현재 운영 사실을 확정할 수 없다. 고객용 화면에서는 검증되지 않은 수치·혜택·보장을 생략하고, 필요한 경우 예약 채널의 해당 상품 조건으로 연결한다.

## 7. 작업 경계와 현재 상태

이번 범위는 격리된 정적 홈페이지 시안과 내부 검토 자료다. 기존 원본과 운영 환경을 보존한다. 운영 배포, 공개 배포, PR 생성·병합, 고객 발송, 예약·요금·재고·결제 변경은 이번 작업에 포함하지 않는다.

현재 이 문서는 테스트 결과를 기록하지 않는다. 구현 파일의 존재, 실행 여부, 화면 검수, 공개 승인, 실제 사용을 각각 확인해야 한다. ‘작동하도록 작성했다’와 ‘검수에서 통과했다’는 별도로 보고한다. 검색·전환·매출 향상 효과는 아직 측정하지 않았다.

## 8. 후속 첫 순서

1. **현재 시안의 화면과 핵심 행동 검수** — 데스크톱·모바일에서 히어로, 목적 선택, 이미지 변경, 갤러리, FAQ, OTA 링크를 확인한다. 가로 넘침·한글 잘림·키보드·reduced-motion·이미지 실패·콘솔 오류를 함께 기록한다.
2. **선택한 사진과 객실을 대조** — 세 대표 유형부터 원본·보정본·실제 객실·판매 유형 연결을 확인하고, 확인이 끝난 범위에서 공개 목록을 넓힌다.
3. **운영정보와 공개 조건 확정** — 누락된 연락처·정원·특화시설·도착 안내·상품 조건, 사진 권리와 고객 공개 범위를 담당자 확인으로 채운다.
4. **공개용 버전 검수와 배포 판단** — 시안과 공개용 결과물을 구분한다. 운영 도메인·메타·canonical·robots·사이트맵·실제 예약 경로를 확정한 뒤 별도 승인 범위에서 공개한다.
5. **백엔드·검색·사례 확장** — 필요 기능과 제공 가능한 데이터를 먼저 정한다. 클릭, OTA 이동, 확정 예약, 투숙, 매출을 구분하고 검증된 결과만 사례에 반영한다.

다음 첫 행동은 **현재 시안에서 대표 객실을 선택했을 때 사진과 설명이 같은 객실을 가리키는지 확인하는 것**이다. 화면의 인상이 충분히 정리된 뒤 운영값과 확장 기능을 연결한다.
